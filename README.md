# UNO CAFE LOUNGE — تحدي النرد 🎲

لعبة تسويقية تفاعلية **بدون أي لمس** لكافيه UNO CAFE LOUNGE: يلعب الزبون بحركة إيده فقط أمام كاميرا الجهاز — كف مفتوح لبدء التحدي، سكّر إيدك وافتحها لترمي النرد، ويظهر الخصم مباشرة على الشاشة.

اللعبة تطبيق ويب **ثابت 100%** (HTML5 + CSS3 + JavaScript خالص + MediaPipe Hand Landmarker): لا خادم، لا قاعدة بيانات، لا npm، لا خطوة بناء — تُنشر مباشرة على GitHub Pages أو أي استضافة ثابتة.

> ⚠️ **متطلب أساسي:** الكاميرا تعمل فقط عبر **HTTPS** أو **localhost**. المتصفح يطلب إذن الكاميرا مرة واحدة، وبعدها تعمل اللعبة تلقائياً بالكامل بدون أي نقرة أو لمسة.

## 1) نظرة عامة على التجربة

| المرحلة | ما يراه الزبون | كيف يتحكم بها |
|---|---|---|
| الترحيب | شعار أونو + «تحدي النرد» + «جرّب حظك واربح خصمك!» | تلقائياً عند فتح الصفحة |
| تشغيل الكاميرا | «جاري تشغيل الكاميرا...» + تعليمات الإذن | تلقائياً (إذن المتصفح هو التفاعل الوحيد المطلوب) |
| انتظار اليد | «وجّه إيدك نحو الكاميرا» | كف مفتوح ثابت 700ms يبدأ العد |
| العد التنازلي | «استعد!» ثم 3، 2، 1، GO! | تلقائياً — إن غابت اليد يُلغى العد |
| تسليح الرمية | «سكّر إيدك، وبعدين افتحها لترمي النرد!» | قبضة مسكّرة ثابتة 300ms |
| الرمية | «ممتاز! هسا افتح إيدك لترمي النرد.» | فتح الكف يرمي النرد مرة واحدة |
| الرمي | نرد ثلاثي الأبعاد يقفز ويدور ~2.2 ثانية | تلقائياً — الإيماءات مقفلة أثناء الأنيميشن |
| الجائزة | النتيجة + الخصم + كود المرجع + «اعرض النتيجة للكاشير» | تلقائياً |
| إعادة اللعب | «سكّر إيدك وثبّتها لمدة ثانية» | قبضة ثابتة 1000ms تعيد الجولة |

**ممنوع حسب التصميم:** أي زر، لمس شاشة، لوحة مفاتيح، أو فأرة في مسار الزبون. الاستثناء الوحيد هو زر «السماح» في نافذة إذن الكاميرا الخاصة بالمتصفح نفسه.

## 3) استبدال شعار UNO CAFE

الشعار الحالي **بديل مؤقت مرسوم برمجياً وليس الشعار الرسمي**. لاستبداله:

1. ضع ملف الشعار الرسمي في `assets/` باسم `uno-cafe-logo.png` (نفس الاسم = بدون أي تعديل كود).
2. أو غيّر المسار في `js/game-config.js`:

```javascript
logoPath: "assets/your-new-logo.png",
```

- يُحترم تناسب الصورة تلقائياً (aspect ratio)، وتظهر في أعلى الصفحة وشاشة الترحيب وبطاقة الجائزة.
- إذا فشل تحميل الصورة أو كان الملف مفقوداً، يظهر **بديل نصي** بكلمة UNO CAFE LOUNGE تلقائياً — لا تنكسر الواجهة.

## 4) التشغيل محلياً (localhost)

الملفات المفتوحة مباشرة بـ `file://` **لن تعمل** (المتصفحات تحجب الكاميرا ووحدات ES Module). اختر أي طريقة:

**بايثون (مثبّت غالباً):**
```bash
cd uno-cafe-dice-game
python3 -m http.server 8000
# افتح: http://localhost:8000
```

**VS Code:** إضافة **Live Server** → كليك يمين على `index.html` → *Open with Live Server*.

**Node (اختياري):**
```bash
npx serve uno-cafe-dice-game
```

عند أول فتح سيسألك المتصفح عن إذن الكاميرا → اختر **السماح**. الإذن يُحفظ عادةً للنطاق نفسه، فالمرة القادمة تعمل اللعبة فوراً بدون أي سؤال.

**متطلب إنترنت عند التشغيل:** مكوّن MediaPipe وخطوط جوجل تُحمّل من CDN عند أول فتح (~3 ميجابايت). بعد أول تحميل غالباً تُخزَّن في الذاكرة المؤقتة.

## 6) تعديل إعدادات اللعبة (`js/game-config.js`)

هذا الجدول يلخص أهم المفاتيح — كلها في ملف واحد بدون لمس محرك اللعبة:

| المفتاح | الافتراضي | الوظيفة |
|---|---|---|
| `brandName` | "UNO CAFE LOUNGE" | الاسم الظل في الواجهة |
| `logoPath` | assets/uno-cafe-logo.png | مسار الشعار |
| `dice.minValue / maxValue` | 1 / 6 | نطاق وجوه النرد (مقيد بـ 1..6) |
| `dice.rollDurationMs` | 2200 | مدة أنيميشن الرمي (مسموح 1000–3000) |
| `probability.enabled` | true | تشغيل التوزيع المرجّح (false = نرد عادل) |
| `probability.targetNumber` | 6 | الرقم «الهدف» المرتبط باحتمال معلن |
| `probability.weights` | انظر القسم 7 | وزن كل وجه |
| `probability.targetProbability` | 1/1000 | الاحتمال المعلن للرقم الهدف — يُتحقق من تطابقه مع الأوزان |
| `camera.stableDetectionMs` | 700 | ثبات الكف المطلوب لبدء العد |
| `camera.fistHoldMs` | 300 | ثبات القبضة لتسليح الرمية |
| `camera.openPalmHoldMs` | 150 | ثبات فتح الكف لتفعيل الرمية |
| `camera.restartFistHoldMs` | 1000 | ثبات القبضة على شاشة الجائزة لإعادة الجولة |
| `camera.lostHandToleranceMs` | 800 | مهلة فقدان اليد قبل إلغاء العد/الإيماءة |
| `camera.hand*Confidence` | 0.65 | عتبات ثقة كشف/تتبع اليد (0..1) |
| `countdown.seconds` | 3 | عدد ثواني العد التنازلي (1..10) |
| `rewards` | انظر القسم 9 | عنوان الجائزة ونسبة الخصم لكل وجه |
| `promotion.terms` | نص الشروط | يظهر على بطاقة الجائزة |
| `promotion.requireOddsDisclosure` | true | إظهار بند إفصاح الاحتمالات في شاشة الترحيب |
| `game.maxThrowsPerSession` | 1 | أقصى رميات في الجلسة الواحدة (الإعادة بالإيماءة تبدأ جلسة جديدة) |
| `game.testMode` | false | وضع المطور (القسم 11) |
| `audio.enabled` | true | المؤثرات الصوتية المولّدة |

عند فتح الصفحة يُفحص ملف الإعدادات تلقائياً؛ أي خطأ (وزن سالب، احتمال متناقض، جائزة ناقصة...) يوقف اللعبة ويعرض رسالة واضحة بدل السماح بسلوك خاطئ بصمت.

## 7) الاحتمالات: الأوزان واحتمال 1 من 1000

### الوضع المرجّح (المفعّل افتراضياً)

احتمال كل وجه = وزنه ÷ مجموع الأوزان. الافتراضي:

```javascript
weights: { 1: 200, 2: 200, 3: 200, 4: 200, 5: 199, 6: 1 }
```

- المجموع = 200+200+200+200+199+1 = **1000**
- إذن: P(1)=20%، P(2)=20%، P(3)=20%، P(4)=20%، P(5)=19.9%، **P(6)=1/1000=0.1%**

هذا بالضبط مثال «احتمال الهدف 1 من 1000»: أي تعديل للأوزان يجب أن يُبقي المعادلة متطابقة مع `targetProbability`، وإلا رفضت اللعبة الإعدادات برسالة خطأ (لا تُقبل إعدادات متناقضة بصمت).

**لتغيير احتمال الهدف** مثلاً إلى 1 من 100 (على الوجه 6): اجعل مجموع الأوزان 100 ووزن الوجه 6 هو 1، واضبط:

```javascript
targetProbability: { numerator: 1, denominator: 100 }
```

**لتغيير الرقم الهدف** من 6 إلى وجه آخر: عدّل `targetNumber` وانقل الوزن النادر إلى الوجه الجديد ثم راجع تطابق `targetProbability`.

### الفرق بين النرد المرجّح والنرد العادل

| | النرد المرجّح | النرد العادل |
|---|---|---|
| الاحتمال | كل وجه حسب وزنه | 1/6 لكل وجه تماماً |
| التحكم | `probability.weights` | — |
| الاستخدام | تسويقي (خصم 20% نادر) | عروض «حظ عادل» للجميع |
| التفعيل | `probability.enabled: true` | `probability.enabled: false` |

### العشوائية

الاختيار يستخدم `crypto.getRandomValues()` بخوارزمية **rejection sampling** تلغي انحياز باقي القسمة (modulo bias). عند غياب crypto (متصفح قديم جداً) يُستخدم `Math.random()` كحل بديل موثّق داخل الكود.

### ⚠️ شفافية إجبارية

إعدادات الاحتمالات كود JavaScript يعمل على جهاز الزبون — **قابل للفحص والتعديل من أي شخص ولست سرية ولا مقاوِمة للتلاعب**. لا تستخدمها أبداً كأساس لعروض نقدية ذات قيمة عالية، وضع بند الشروط في `promotion.terms`.

## 8) توقيتات الإيماءات وضبط الحساسية

كل التوقيتات بالمللي ثانية في `camera` (جدول القسم 6). توصيات ضبط:

| المشكلة | الحل |
|---|---|
| العد يبدأ قبل أن يثبّت الزبون يده | ارفع `stableDetectionMs` إلى 900–1000 |
| القبضة لا «تُسلّح» الرمية بسرعة | ارفع `handTrackingConfidence` قليلاً أو خفّض `fistHoldMs` إلى 200 |
| رميات عشوائية من حركة سريعة | ارفع `openPalmHoldMs` إلى 250–300 |
| إعادة اللعب سهلة جداً على الأطفال | ارفع `restartFistHoldMs` إلى 1500 |
| اليد تختفي لحظياً فيقطع العد | ارفع `lostHandToleranceMs` إلى 1200 |

كما تؤثر عتبات `hand*Confidence` الثلاثة (0..1): قيم أعلى = كشف أكثر تحفظاً (يحتاج إضاءة أفضل)، قيم أدنى = كشف أسهل لكن أكثر هشاشة.

## 9) الجوائز والخصومات

التعريف كله من `rewards` في ملف الإعدادات — الافتراضي:

| النتيجة | العنوان الظاهر | الخصم |
|---|---|---|
| 1 | حظ أوفر في المرة القادمة | 0% |
| 2 | مفاجأة من أونو | 0% |
| 3 | خصم 5% | 5% |
| 4 | خصم 10% | 10% |
| 5 | خصم 15% | 15% |
| 6 | خصم 20% | 20% |

لتعديل جائزة:

```javascript
4: { title: "كوفي مجاني", discountPercent: 0 },
```

- إذا كان `discountPercent > 0` تُعرض بطاقة ذهبية بنبض + عبارة «مبروك! ربحت ...».
- على البطاقة تظهر تلقائياً: الشعار، نتيجة النرد، العنوان، النسبة، عبارة «اعرض النتيجة للكاشير للحصول على جائزتك.»، **كود مرجع** مثل `UNO-K7M3XQ9A`، ونص الشروط من `promotion.terms`.
- كود المرجع يُولّد عبر `crypto.getRandomValues()` بحروف بدون رموز ملتبسة (بدون O/0/I/1).

## 10) الخصوصية

- المعالجة محلية 100% داخل المتصفح: **لا تسجيل ولا رفع ولا تخزين** لأي إطار فيديو.
- لا يوجد تتبع للوجه أو العين — تتبع اليد فقط (21 نقطة مفصلية).
- إشعار الخصوصية ظاهر دائماً أسفل الشاشة: «نستخدم الكاميرا لاكتشاف حركة اليد فقط. لا يتم تسجيل الفيديو أو رفعه إلى أي خادم.»
- عند إغلاق الصفحة أو إعادة تحميلها تُوقف مسارات الكاميرا وتُحرَّر كل الموارد (مستمعو الأحداث وحلقات الرسم تنظف تلقائياً).
- لا يوجد أي إرسال بيانات لأي خادم — التطبيق ثابت بالكامل.

## 11) وضع المطور (testMode)

فعّله في `js/game-config.js`:

```javascript
game: { maxThrowsPerSession: 1, testMode: true }
```

يضيف:

- **لوحة تشخيص جانبية:** الحالة الحالية، الإيماءة الخام (`NO_HAND` / `UNKNOWN` / `OPEN_PALM` / `CLOSED_FIST`)، مدة الثبات، FPS، عدد رميات الجلسة، حالة الكاميرا، وسجل أحداث مباشر لانتقالات الإيماءة.
- **محاكاة إيماءات** (كف مفتوح / قبضة / بلا يد) لاختبار كامل التدفق بدون كاميرا — مفيد جداً قبل التركيب.
- **فرض نتيجة النرد** لفحص مطابقة الجائزة لكل وجه + زر «عرض الجوائز» يطبع خريطة الجوائز والاحتمالات الفعلية.
- **اختبار تحرير الكاميرا** (إيقاف/تشغيل) وتصفير عدّاد الجلسة.
- كائن `window.UNO_DEBUG` في وحدة التحكم (Console).
- شارة الإيماءة فوق معاينة الكاميرا.

**في الوضع العادي (testMode: false) لا يظهر أي عنصر تقني للزبون إطلاقاً.** وضع المطور أدوات اختبار معلنة — لا يحاول الكود إنشاء «رابط سري» أو كلمة مرور عبر JavaScript لأن ذلك غير آمن بطبيعته.

### تشغيل الاختبارات الآلية

**بالمتصفح:** افتح `tests.html` عبر خادم محلي — تعرض 45 اختباراً تغطي: التحقق من الإعدادات، حدود الأوزان، تطابق 1/1000، التوزيع الإحصائي (20,000 رمية)، عدم انحياز العشوائية، الجوائز، أكواد المرجع، تصنيف الإيماءات من معالم يد اصطناعية، وآلة الحالة كاملة (منع التكرار، الإلغاء، إعادة الجولة).

**بالطرفية (بدون تبعيات):**
```bash
node scripts/run-tests.mjs   # من المجلد الأعلى للمشروع كما هو مسلّم
```
(إن فُصل المجلد عن السكربتات، افتح `tests.html` بالمتصفح — نفس النتيجة.)

### قائمة الفحص اليدوية (تحتاج كاميرا حقيقية)

نفّذها على الجهاز النهائي قبل التشغيل الفعلي — الاختبارات الآلية أعلاه لا تغطيها لأنها تتطلب عتاد كاميرا:

| # | السيناريو | المتوقع |
|---|---|---|
| 1 | فتح الصفحة وإعطاء الإذن | شاشة ترحيب ثم انتقال تلقائي بدون أي نقرة |
| 2 | رفع كف مفتوح وثباته | عد تنازلي يبدأ تلقائياً بعد ~0.7 ثانية |
| 3 | سكّر إيدك | رسالة «ممتاز! هسا افتح إيدك...» و**لا رمية** بعد |
| 4 | فتح الكف بعد القبضة | رمية واحدة فقط مع أنيميشن |
| 5 | فتح الكف بدون تسكير مسبق | لا شيء يحدث |
| 6 | إبقاء الكف مفتوحاً طويلاً بعد الرمية | لا رميات إضافية |
| 7 | تحريك اليد أثناء أنيميشن النرد | لا تأثير |
| 8 | مطابقة النتيجة مع الأوزان | في testMode فرض النتيجة يطابق الجائزة |
| 9 | إخفاء اليد أثناء العد | يُلغى العد وتظهر «ما قدرنا نشوف إيدك...» |
| 10 | قبضة ثابتة على شاشة الجائزة | إعادة الجولة ثم يتطلب تسلسلاً كاملاً جديداً |
| 11 | قطع الكاميرا أثناء اللعب | رسالة خطأ ثم استرجاع تلقائي عند عودتها |
| 12 | رفض الإذن ثم منحه من الإعدادات | اللعبة تستأنف تلقائياً خلال ≤8 ثوانٍ |
| 13 | إغلاق التبويب | لا يبقى ضوء الكاميرا مضاءً (تحرير المسارات) |
| 14 | تجربة كاملة بدون لمس الشاشة | كل التدفق بالإيماءات فقط |
| 15 | النشر على GitHub Pages | تعمل من رابط HTTPS مباشرة |

|---|---|---|
| «إذن الكاميرا مرفوض» | رُفض الإذن سابقاً | أيقونة القفل بجانب العنوان → الكاميرا → سماح؛ اللعبة تستأنف تلقائياً |
| «ما في كاميرا موصولة» | لا كاميرا أو معطّلة نظامياً | وصّل/فعّل الكاميرا — الاكتشاف تلقائي |
| «الكاميرا مستخدمة من برنامج ثاني» | Zoom/Teams وغيرها | أغلق التطبيقات المستخدمة للكاميرا |
| «يلزم HTTPS أو localhost» | فتحت الصفحة بـ file:// أو http:// غير آمن | شغّل عبر localhost أو انشر على GitHub Pages |
| شاشة سوداء مع تشغيل ناجح | تعريف كاميرا ضعيف | جرّب متصفحاً آخر أو أعد توصيل الكاميرا |

اللعبة تعيد المحاولة تلقائياً كل 8 ثوانٍ في حالة الخطأ، وتستأنف فور منح الإذن دون أي نقرة.

### مشاكل MediaPipe / تتبع اليد

| المشكلة | الحل |
|---|---|
| «تعذّر تحميل نظام تتبع اليد» | تأكد من اتصال الإنترنت عند أول تشغيل (يُحمّل من jsdelivr) |
| بطء الكشف الأول | انتظار 5–15 ثانية لأول تحميل للنموذج (~3MB) |
| كشف متقطع | حسّن الإضاءة، اجعل الخلفية بلا أنماط ملتوية، المسافة 40–80 سم |
| رسوم متحركة ثقيلة | بعض الأجهزة القديمة لا تدعم GPU delegate — يتحول الكود تلقائياً إلى CPU |
| متصفح قديم | استخدم آخر إصدار من Chrome/Edge/Safari/Firefox (يلزم ES2020 + WebGL) |

### ملاحظة الإضاءة المهمة

كشف القبضة يعتمد على مواضع مفاصل الأصابع؛ الإضاءة الجانبية القوية أو الخلفية الشمسية المباشرة قد تضعف الدقة. الإضاءة الأمامية المتزنة مثالية.

## 13) حدود كود القسيمة الثابت (مهم تجارياً)

كود المرجع المعروض (`UNO-XXXXXXXX`) **وسيلة تذكير للكاشير وليس نظام حماية**:

- ✅ **لا يمنع:** تصوير النتيجة لاحقاً، تعديلها بأدوات المطور، أو إعادة عرضها في زيارة ثانية.
- ✅ **لا يتحقق من:** أن الكود لم يُستخدم من قبل — لا يوجد سجل لأن التطبيق ثابت بلا خادم.
- 🔒 **لفرض استخدامٍ واحد موثوق:** تحتاج خلفية (Backend) أو تكامل مع نظام نقاط البيع (POS) — مثلاً فحص الكود عند الكاشير مقابل قائمة يومية، أو توليد QR من نظام قسائم حقيقي.

صُممت اللعبة بوصفها **مرساة تجربة وترفيه تسويقي أمام الكاشير** (الكاشير يرى النتيجة لحظتها)، وهذا استخدام سليم وواقعي.

## 14) ملاحظات تقنية للمطوّرين

- **بنية معيارية:** الإعدادات، الاحتمالات، الجوائز، الرؤية، آلة الحالة، الواجهة — ست وحدات مستقلة؛ آلة الحالة نقية بلا DOM ولهذا تُختبر آلياً بسهولة.
- **حلقة معالجة واحدة:** `requestAnimationFrame` واحدة مع تجاهل الإطارات المكررة عبر `video.currentTime`.
- **منع الرميات المزدوجة:** ثلاث طبقات — قفل إيماءة (`throwLock`)، بوابة الحالة، وعدّاد الجلسة.
- **التنعيم:** EMA على معالم اليد + debounce ثنائي الإطار قبل اعتماد تغيّر الإيماءة + وضعيات `UNKNOWN` لا تُقبل كقبضة أو كف.
- **الأنيميشن لا يحدد النتيجة:** محرك الاحتمالات يختار الوجه قبل الأنيميشن؛ لفات المكعب الإضافية مضاعفات 360° فتنتهي حتماً على وجه النتيجة، والأنيميشن يحترم `prefers-reduced-motion`.
- **الصوت:** مؤثرات مولّدة عبر WebAudio (بدون ملفات صوت) — الصوت اختياري وكل المعلومات متوفرة بصرياً؛ سياسات التشغيل التلقائي قد تمنع الصوت قبل أول تفاعل نظام، وهذا مقصود وغير مؤثر.
- **نسخ CDN مثبتة:** `@mediapipe/tasks-vision@0.10.14` وخطوط Cairo/Tajawal عبر Google Fonts.
- لم تُستخدم Bootstrap — التصميم مخصص بالكامل ويبقى أخف وأسرع.
